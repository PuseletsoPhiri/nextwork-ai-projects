# BUILD A BLOG WRITING CREW WITH CREWAI



## Introducing Today's Project!

In this project, I'm going to build a multi-agent system using CrewAI to research, write and edit a blog post for me. I'm interested in this because I want to learn how to easily deploy multi-agent systems

### Key tools and concepts

The key tools I used include CrewAI, Gemini API Key and Python (with uv). Key concepts I learnt include things like multi-agent systems and giving prompting well by being explicit about the role, task and backstory because all of this makes a big difference in the output

### Challenges and wins

This project took me approximately 1 hour 30 minutes. The most challenging part was while setting up and running my CrewAI blog-writing crew using the new JSONC-based template.

First, I had to verify that Python was installed correctly and configure my environment so that Python and pip worked from the terminal. Next, I needed to adapt the project instructions from the older YAML-based CrewAI examples to the newer JSONC project structure generated by CrewAI.

I then encountered multiple Gemini model configuration issues, including model availability errors and service availability errors. To resolve this, I tested different model configurations and verified that Gemini 3.8 Flash worked with my API key and CrewAI setup.

Another challenge was determining whether the issue was with CrewAI or Gemini. I solved this by testing Gemini directly through LiteLLM, which confirmed that the API key, Gemini model, and environment were working correctly.

I also experienced long execution times and API failures while running the crew. After investigation, I discovered that the project had reached the Gemini free-tier request limits for the day, resulting in quota-related errors. This explained why some runs failed even though the configuration was correct.

Finally, I extended the crew by adding a new social media manager agent, creating a social media content generation task, and configuring an output file to save the generated social media posts.

## Defining the Task Pipeline

In this step, I'm defining the tasks that each agent is responsible for and connecting the task to each responsible agent. These tasks are important because they allow each agent to know exactly what to do and what their job and role is

![Defining the Task Pipeline](https://nextwork.ai/exuberant_purple_zany_armadillo/uploads/99b558af-381c-5c9e-afef-a2d5e19992c0_p3n8v5w1)

### How the tasks chain together

The three tasks chain together through the sequential process defined in crew.jsonc. First, the {topic} research analyst researches the chosen topic and creates a detailed research brief. That research brief is automatically passed to the {topic} blog writer, who uses it to create a complete blog post. The resulting draft is then passed to the Senior Content Editor, who reviews, polishes, and improves the content before producing the final version.

Only the editing task has an output\_file field because it generates the final deliverable that should be saved. The research and writing tasks produce intermediate outputs that are used by subsequent agents in the workflow, while the editor's task produces the publication-ready blog post that needs to be written to a file for future use.

## Connecting YAML Configuration to Python

I'm connecting my agents and tasks through the crew.jsonc configuration file instead of crew.py. The new CrewAI template uses JSONC-based configuration, where agents, tasks, and the crew workflow are defined declaratively.

The crew.jsonc file links my researcher, writer, and editor agents to their respective tasks and specifies a sequential process so each agent receives the previous agent's output.

Instead of updating main.py, the crew is executed directly through the CrewAI CLI. Runtime inputs such as {topic} are provided when running crewai run, allowing the crew to generate a blog post on any topic entered by the user.

### Extending the crew with new agents and tasks

I added the social media manager by creating agents/social\_media\_manager.jsonc and defining the new agent's role, goal, backstory, LLM, and settings. Then, in crew.jsonc, I added social\_media\_manager to the agents list and created a new create\_social\_media\_content\_task for generating social media posts.
